# VecBeamMAME ベクターチェイン

English: [README.md](README.md)

較正済みチェインが VecBeamMAME の標準のベクター表示構成です。

- `vector-color`
- `vector-monochrome`
- `vector-vectrex`
- `default-vector`（最小構成のフォールバック）

MAME のビデオオプションから選ぶか、`-video bgfx -bgfx_screen_chains <チェイン名>` で指定します。
BGFX スライダーの値はゲームごとに MAME の設定ファイル（`cfg/<game>.cfg`）へ保存されます。

カラー機／モノクロ機／Vectrex は対応する標準チェインを自動で選びます。そのチェインが無い、
あるいは読み込みに失敗した場合は `default-vector` にフォールバックします。未知のベクター
ハードウェアも `default-vector` を使います。

旧 `*-balanced` 系の名前は既存の設定ファイルを読むときに受け付け、標準名へ移行されます。

## 標準チェインの較正

標準の既定値には現時点の機種別較正が入っています。保存済みの設定ファイルは必要ありません。

- `vector-color` — *STAR WARS* のオーバーロード起因 HV 垂下の較正を含みます。
- `vector-vectrex` — Vectrex の残光、ビーム／点、フォーカス、ハレーション、グローバッファ、
  スターバースト、環境光、グローの尾、両面印刷オーバーレイの較正を含みます。オーバーロードの
  幾何的な幅の制御は、既定ではオーバーロードのブルームから独立しています。孤立した滞留ドットの
  最小サイズ、蛍光体色のポストグロー、管面／オーバーレイ／通常のベゼルアートワークに共通で効く
  室内光の制御（UI は除く）も提供します。
- `vector-monochrome` — *ASTEROIDS* の点、フォーカス、ハレーションの塗り、スターバースト長、
  環境光の較正を含みます。

ゲームごとの設定ファイルはこれらの既定値を上書きできます。チェインの既定値そのものを評価したい
ときは、保存された BGFX スライダーの項目を消すか、UI でスライダーをリセットしてください。

Vectrex の既定値は現在のリファレンス `vectrex.cfg` の較正に揃えてあります。蛍光体 RGB
`[0.50, 0.70, 1.00]`、孤立滞留ドット最小サイズ `3.0 px`、室内光 `0.50`、較正済みの両面
オーバーレイ応答などです。

## オーバーロード起因の HV 垂下

HV 垂下は高圧電源の垂下を、全体の減光とスポットのボケとして模擬します。通常のベクターの本数や
エネルギーの合計で駆動されるのではありません。レンダラは**点ではない線プリミティブについて、
`Overload Threshold` を超えた分のエネルギーだけ**を合計します。

```text
overload load =
    sum(max(線のエネルギー − overload threshold, 0)
        × 線の長さ / 基準画面幅)

droop load =
    clamp((ピーク追従した overload load − HV Droop Overload Onset)
          / HV Droop Load Ref, 0, 1)
```

`HV Droop (dim+defocus)`
: 効果の最大の強さ。値 1.0 で負荷が最大のとき、線の堆積は最大 40 % 減光され、スポットの σ が
  基準幅 1920 px において約 2.5 px 増えます。

`HV Droop Overload Onset`
: 孤立した、あるいは低レベルのオーバーロードを弾きます。この値以下の負荷では減光もボケも
  まったく起きません。

`HV Droop Load Ref`
: onset を超えてからどれだけ追加のオーバーロードで最大の垂下に達するか。小さくすると、
  大規模なオーバーロードが早く最大に達します。

この負荷を発生させられるのは `Overdrive (hot core)` が有効なチェインだけです。滞留点は対象外
なので、熱い弾 1 発や静止したドットが画面全体を暗くすることはありません。ピーク追従はソース
フレームごとに 0.82 倍で減衰するので、大きなイベントの後に短い復帰が入ります。

`vector-color` の出発値:

```text
HV Droop (dim+defocus)   0.50
HV Droop Overload Onset  0.50
HV Droop Load Ref        5.00
```

通常のプレイでも孤立したオーバーロード線が多く、目に見える垂下が起きるなら onset を上げます。
デス・スター爆発のような大きなイベントで狙った強さに届かないなら load ref を下げます。

## グロー、ハレーション、コンバージェンス散乱

`Glow Narrow` と `Glow Wide` が通常の近距離・広域の線グローです。広域グローの到達距離を伸ばした
ことで、かつて独立した Convergence Bloom 機能が作っていた広い局所ハローもこちらが担うように
なったため、局所 Convergence Bloom とその 6 本の調整用スライダーは撤去しました。

`Convergence Global Bloom` は標準チェインに残っています。大きく連結したオーバーロード領域を
検出して、管面全体に広がる散乱を足します。コンパクトな局所オブジェクトには専用の
コンバージェンスハローは付きません。散乱の広さは `Convergence Global Coverage` で決めます。

点の光学系の制御はスライダーメニュー上で物理的な順に並べてあります。

1. ハレーションのゲインとリング
2. スターバーストのゲイン、本数、長さ、ランダム性、幅、角度
3. 通常の解析グロー

Deflection Dynamics とその整定／減衰の制御はチェインから撤去しました。ベクターの幾何は
レンダラ側の 2 次偏向シミュレーションを通さず、ソースの軌跡そのままで描かれます。

## 高リフレッシュ提示

VecBeamMAME は、エミュレーションやソースのベクターフレームレートを上げずに、モニタの
リフレッシュレートでベクター出力を提示できます。

```text
vector_present_rate auto
vector_phosphor_rate 0
```

`vector_present_rate` が取る値:

- `0` — 提示のみの更新を無効にします。
- `auto` — BGFX ウィンドウの初期化後に、実際のモニタのリフレッシュレートを取得します。Windows
  では小数を含むデスクトップのレートを問い合わせ、最も近い整数の提示レートに丸めます
  （例: 143.988 Hz は 144 Hz で提示）。macOS ではウィンドウの `NSScreen` の最大フレームレート
  を使います（通常 60 Hz、ProMotion ディスプレイなら最大 120 Hz）。
- `1`〜`360` の数値 — 固定の提示レートを指定します。

追加の present は直近に完成したベクター出力を使い回します。エミュレートされたマシンのフレームを
もう 1 回走らせることはなく、ゲームの速度も変えず、`-nothrottle` が提示レートに依存することも
ありません。

`vector_phosphor_rate` は、提示は要求どおり続けたまま、負荷の高い時間方向の蛍光体／モニタ
チェインだけを制限します。

- `0` が既定で、present のたびにチェインを更新します。
- `1`〜`360` の数値でチェインの更新をそのレートに制限します。新しいソースのベクターフレームが
  遅れることはありません。その間の present は完成済みの出力を使い回します。

短い滞留の点と線端は持続を持たないバッファを使います。その内容は同じソースフレームの提示のみの
繰り返しをまたいで保持され、次のソースフレームで置き換わります。これにより小さな星やドットが
ソースと提示のビート周波数で点滅するのを防いでいます。

`-waitvsync` は従来どおりバックエンドのスワップチェイン同期の制御です。提示タイマとは独立して
おり、スロットルを外した速度をモニタのリフレッシュレートで頭打ちにすることがあります。

## MVEC の記録と再生

`-vector_record <file.mvec>` で最終的なベクタービーム事象を記録し、
`-vector_playback <file.mvec>` で再生します。この 2 つは排他です。記録時には音声も
`<file.mvec>.wav` に書き出します。

MVEC フォーマット 1.1 はソースのベクターフレーム周期をファイルヘッダに持ちます。再生時は
その周期からベクタースクリーン、再生クロック、音声同期、フレーム基準の表示効果を自動で設定
します。1 つの MVEC フレームを高リフレッシュで繰り返すとき表示時間は進まないので、蛍光体の
減衰やフリッカはホストの present ごとではなく記録されたフレームごとに 1 回進みます。

フォーマット 1.0 のファイルも読めます。時刻情報を持つベクターストリームなら、ビーム事象の
絶対時刻からソースのレートを推定します。使える時刻情報がまったくない古いファイルでは、現在の
ベクタースクリーンのレートにフォールバックし、その旨をログに出します。

同梱の [MVEC ビューア](../../../tools/mvec-viewer/) をブラウザで開くと、記録した
ビーム事象ストリームを可視化できます。

## 撤去したパラメータ

チェインの既定値ではコード経路に到達しないパラメータは、ロジックごと削除しました。すりガラスの
光学モデル、管面歪みの 3 次項とコーナー項、ピンクッション係数 4 本のうち 3 本、ベゼル内側の
ローブ、蛍光体の診断ビュー、P22 蛍光体ガマットのブレンド、HDR 診断オーバーレイ、T 字接合部の
キャップ抑制、時刻情報を持たない走査順のばらつき — これらはすべて無くなりました。ピンクッション
の制御として残っているのは `Vector Pincushion X (Quad)`（`vector_pincushion_x_quad`）です。

コンバージェンス（`converge_*`、`radial_converge_*`、`convergence_global_*`）と
`Vector Linearity X/Y`（`vector_linearity_x` / `vector_linearity_y`）は実機との位置合わせに
使うため残してあります。Advanced 側にあり、既定の 0 では処理コストもかかりません。

すりガラスが無くなったので、`wide_glow_ds0..ds3` のダウンサンプルパスは `Glow Wide`
（`glow_wide`）だけを見てスキップされます。
